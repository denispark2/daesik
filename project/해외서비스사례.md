## 요약
- Smartify는 런던의 사회적기업이 만든 미술관 디지털 가이드 플랫폼이다 (제휴 기관 1,200곳 이상).
- 추천은 세 갈래다. 도시 단위 '다음에 볼 것' 추천, 미술관 안 **AI 개인 맞춤 투어**, 기관용 행동 데이터 알림.
- AI 개인 맞춤 투어가 우리와 가장 가깝다. **관심사 + 꼭 볼 작품 + 가진 시간**을 받아, 작품을 맞추고 **작품 사이 거리**를 계산해 시간 안 경로를 만든다.
- 알고리즘 자체는 공개되지 않았다.
- 우리는 엔진 구조(매칭 + 거리 + 시간 제약)를 가져온다. 다만 입력은 **기차 시간 역산 + 동행**으로, 범위는 **역 → ACC 여러 건물 → 다음 갈 곳**으로 바꾼다.

### 1-2. 추천은 세 갈래다
**① 앱 안 '다음에 볼 것' 추천 (도시 단위)**
- 앱스토어 설명: 위치로 **주변 문화 장소·행사**를 추천하고, 개인 컬렉션을 모으면 **다음에 볼 것 아이디어**를 준다.
- 개인정보처리방침 3.5 '맞춤 제안'(동의한 경우)에서 취향을 분석할 때 쓰는 데이터:
  - 스캔한 작품, 열어 본 작가 정보, 이용 시간과 장소, 즐겨찾기한 작품
  - 누른 링크, 로그인 횟수, IP 기반 위치, 이메일 반응, 앱 이용 방식(동의한 위치 포함), 구매
  - 프로모션 참여, 설문 응답
  - 계열사가 가진 데이터, **제3자에게서 받은 사회·인구 정보**
- 결과물: 공연·행사·상품 할인 쿠폰 같은 맞춤 제안 (이메일 또는 앱)
- 2017년 기사: 즐겨찾기한 작품으로 비슷한 작품을 추천한다고 소개됐다.

**② AI 개인 맞춤 투어 (한 미술관 안 경로) ← 우리 서비스와 가장 가깝다**
- 방문자 입력: **관심사 선택 + 꼭 볼 작품(must-see) + 가진 시간** (+ 언어)
- 엔진 (Smartify 설명): 관심사를 **지금 전시 중인 작품**과 맞추고, **작품 사이 거리**를 계산해 주어진 시간 안에 가장 알찬 투어를 만든다.
- 결과: 그 미술관의 다른 오디오 가이드 옆에 '내 투어'로 저장되고, 이메일로 받을 수도 있다.
- 사례:
  - 함부르크 쿤스트할레: 1년 시범 운영. Smartify는 독일에서 유일한 AI 개인화 오디오 가이드라고 소개한다. 도입 이유는 미술 지식 수준, **시간 제약**, 관심사가 제각각인 관람객이다.
  - 스미소니언 미국미술관: AI 투어
  - 빌바오 미술관: 4개 언어, 500곳 이상의 AI 디지털 가이드 (제목만 확인)
- 가격: 기관용 요금제 중 **Premium(연 9,500파운드) 이상**에만 들어 있다.

**③ 기관용 행동 데이터 활용 (방문자에게 보내는 추천 알림)**
- 앱이 쌓는 행동 데이터: 스캔, 투어 재생, 위치, 어떤 작품 앞에서 얼마나 머물렀는지, 어디서 투어를 그만뒀는지
- 이 데이터로 관련 전시·행사를 앱 안 알림으로 보낸다. 예: 인상파 오디오를 15분 들은 사람 → 다음 근대미술 전시 안내, 가족 투어를 끝까지 한 사람 → 교육 프로그램 안내
- 관람 중 설문으로 추천 의향 점수(NPS)와 만족도를 잰다 (1-7).
- Smartify 마케팅 책임자 글(2026-01): 동의는 기본값 꺼짐에서 이용자가 켜는 방식, 목적이 끝나면 데이터 삭제를 권한다.

### 1-3. 알고리즘은 공개됐나
- **공개되지 않았다.** 추천 모델, 점수 계산, 가중치를 설명한 기술 자료는 찾지 못했다.
- 공개된 것은 입력값(위 데이터 목록)과 기능 설명(관심사 매칭 + 거리 계산 + 시간 제약)뿐이다.
- 작품 인식은 2017년 기사에서 작품마다 '시각적 지문'을 만든다고만 설명했다.
- ②는 구조상 **'관심사 점수가 높은 작품을, 시간 안에 걸어서 볼 수 있는 순서로 고르는 문제'**로 보인다. 이것은 내 추정이다.

### 1-4. 수익 모델
- 기관 구독: 무료(투어 1개) / Starter 연 1,800파운드 / Branded 연 3,500파운드 / Premium 연 9,500파운드 (AI 개인화 투어, 맞춤 알림) / Bespoke (가격 협의)
- 추가 서비스: 콘텐츠 워크숍 500파운드, 대본·녹음·번역·AR, 지원 시간 시간당 90파운드부터
- 그 밖에 유료 투어·박물관 상점 수익 공유 (검색 요약)

### 1-5. 한계 (이용자 후기)
- 제휴 기관 작품만 인식한다 (2018 후기).
- 2026-01 후기에는 앱이 열리자마자 꺼진다는 내용이 있다.
- 오디오 자동 재생, 화면이 꺼지면 소리가 멈추는 문제가 있었는데 2023년에 고쳤다고 답했다.
- 관람 중에 휴대폰을 드는 것이 다른 관람객을 방해한다는 비판도 있다.

### 1-6. 우리 서비스와 비교 (제안)
| | Smartify AI 투어 | 우리 서비스 |
|---|---|---|
| 시간 | 관람자가 쓸 시간을 직접 고름 | **기차 시간에서 거꾸로 계산** |
| 범위 | 한 미술관 안 | 문화전당역 → ACC 여러 건물 → 다음 갈 곳 |
| 취향 | 관심사·꼭 볼 작품 | 동행 (+ 짧은 성향 문항) |
| 동행 | 언급 없음 | 핵심 입력 |
| 데이터 | 기관이 작품 위치·해설을 등록 | 전시별 관람 시간·건물 간 도보 시간 필요 (아직 미확인) |
- 가져올 것: '꼭 볼 것' 고르기, 작품·전시 간 **거리**로 순서를 정하기, 만든 코스를 이메일·링크로 보내 주기, 관람 뒤 1~2문항 설문.
- Smartify도 **시간 안 경로**를 실제로 팔고 있다. 그러니 우리의 차별점은 '시간 맞춤' 자체가 아니다. **기차 시간 역산 + 동행 + 건물 밖 이동까지 잇는 것**으로 잡아야 한다.

### 1-7. 관람 후기는 모으나
- 누구나 볼 수 있는 공개 관람 후기는 없다.
- 대신 관람 중에 앱 안에서 설문을 띄워 추천 의향 점수(NPS)와 만족도를 계산한다. 결과는 제휴 기관만 본다 (54).
- 관람 뒤에는 그날 본 것을 정리한 안내 메일을 보내고, 몇 주·몇 달 뒤 새 전시를 알린다 (54).

## 2. 우리 프로젝트에 벤치마킹하는 방법 (제안)
전제: Smartify와 ACC는 제휴하지 않는다. 그래서 Smartify가 기관에게서 받는 작품 DB·위치·해설을 우리가 쓸 수 없다. 우리는 **작품 단위가 아니라 전시 단위**로, 공개 정보와 우리가 직접 모은 데이터로 만든다. 기준 문서는 팀 `brand/one-page-plan.md`(입력 2개, 시간 순 코스, 운영자 예측값)다.

### 2-1. 기능별로 가져올 것 / 바꿀 것
| Smartify 기능 | ACC에 적용하는 방식 | 필요한 데이터 | 지금 상태 | 우선순위 |
|---|---|---|---|---|
| **AI 개인 투어** (관심사 + 꼭 볼 것 + 가진 시간 → 작품 매칭 + 거리 계산) | **코스 엔진**: 기차 시간에서 가용 시간을 역산하고, 동행에 맞는 전시를 고른다. 관람 시간 + 전시 간 도보 시간 + 운영·입장 마감을 넣어 시간 안에 드는 조합과 순서를 계산 | 전시별 관람 시간, 건물·층 간 도보 시간, 운영시간·입장 마감 | 운영시간만 확인됨. 관람 시간·도보 시간은 미확인 | 1 |
| 꼭 볼 것(must-see) 고르기 | 입력 2개 기준은 지키고, 코스 화면에서 **"이 전시는 꼭 볼래요"** 한 번 누르면 그 전시를 고정하고 다시 계산 | 없음 (화면 기능) | 시안에 없음 | 2 |
| 관심사 선택 | 관심사 대신 **동행**으로 거른다. 전시마다 태그를 붙여 둔다: 아이와 보기 좋음 / 짧게 볼 수 있음 / 체험형 / 5·18 관련(재촉 금지) | 전시별 태그 | 태그 기준 미정. AI 초안 + 사람 확인 (`전시추천서비스조사.md` 8번) | 1 |
| 작품 사이 거리 계산 | **전시 사이 거리**: 약도를 점과 선(문화전당역 5·6번 출구, 광장, 각 관 입구, 층 이동)으로 만들어 도보 시간을 붙인다. 3D 약도(`brand/route-3d.html`)와 같은 점을 쓴다 | 지점 간 도보 시간 | 미확인. 직접 걸어서 재야 함 | 1 |
| 투어 저장·이메일 전송 | 코스를 **링크·카톡 공유**로 보낸다. 로그인 없이 쓴다 | 없음 | 시안에 없음 | 3 |
| 위치 기반 추천 | GPS 대신 이용자가 **"역에 도착했어요"**를 누르면 그때부터 길 안내 | 없음 | 3D 약도 시안에 '지금 문화전당역' 칩 있음 | 2 |
| 관람 중 설문 (NPS·만족도) | **관람 후 2문항**: "실제로 몇 분 걸렸어요?" "같이 온 분에게 맞았어요?" → 전시별 실제 관람 시간이 쌓인다 | 이용자 응답 | 서비스 운영 후 쌓임 | 1 (데이터 공백을 메우는 핵심) |
| 행동 데이터 → 기관 마케팅 | **운영자 화면**: 실제 관람 시간, 시간이 모자라 빠진 전시, 다음 갈 곳 선택 비율 (one-page-plan 예측값 표와 같음) | 서비스 기록 | 운영 후 쌓임 | 3 |
| 앱 안 알림 | **나갈 시각 알림**: "4시예요. 지금 나가면 5시 기차를 타요." (기차 시간 역산) | 기차 시간 입력 | 문구 규칙은 있음 | 2 |
| AI 번역·음성 | 타깃은 국내 외지 방문객이라 미룬다. 역무원 안내를 소리로 읽어 주는 것만 검토 | — | — | 4 |
| 작품 스캔 인식 | **하지 않는다.** 제휴가 없어 작품 DB가 없고, 관람을 방해한다는 비판도 있다 | — | — | 안 함 |

### 2-2. 코스 엔진 구조 (Smartify 방식 → 우리 방식)
1. 가용 시간 = 기차 시간 − 송정역까지 이동(지하철 24분 + 대기·도보는 따로 잡음) − 여유 시간 (제안값) − 지금 시각
2. 후보 전시 = 지금 열린 전시 중 동행 태그가 맞는 것. 휴관·운영 중단 전시는 뺀다 (ACC 공지 기준)
3. 점수 = 동행 적합 + 기대치 카드의 좋았다는 후기 + (선택) 꼭 볼 전시 고정
4. 순서 = 약도 점·선 그래프에서 이동이 가장 짧은 순서. 층 이동이 있으면 따로 표시
5. 검사 = 관람 시간 + 도보 시간 합이 가용 시간을 넘으면 하나를 빼고 "다 볼 수 없어요"로 안내 (one-page-plan '서비스가 하는 일' 3번)
6. 출력 = 시간 순 코스 + 추천 이유 한 줄(역무원 말투) + 나갈 시각
- 처음에는 AI 모델 없이 **규칙으로 계산**해도 된다. 관람 시간은 확인 전까지 "예시값"으로 표시한다. AI는 태그 초안, 추천 이유 문장, 후기 요약에 쓴다.

### 2-3. 따라 하지 않을 것
- 제3자 사회·인구 정보 결합, 맞춤 할인 쿠폰 같은 마케팅 목적의 데이터 분석 (Smartify 개인정보처리방침 3.5)
- 앱 설치·회원가입을 먼저 요구하는 구조 → 웹에서 바로 쓴다
- 작품 단위 해설 콘텐츠 제작 → ACC 공식 소개 요약과 후기 기대치 카드로 대신한다
- 데이터는 Smartify 마케팅 책임자 글이 권한 대로 **동의한 사람만 모으고, 목적이 끝나면 지운다**

### 2-4. 단계
| 단계 | 할 일 | 끝났다는 기준 |
|---|---|---|
| 1. 시안 | 첫 화면(시간·동행) → 코스 화면 → 3D 길 안내. '꼭 볼래요' 버튼과 나갈 시각 알림을 추가 | 시나리오 20개에서 시간 초과 0건 (one-page-plan 성공 기준) |
| 2. 시범 | 팀원이 직접 걸어서 지점 간 도보 시간을 잰다. 시범 사용자에게 관람 후 2문항을 받는다 | 전시별 관람 시간 표본 확보 (몇 명분인지는 팀이 정함) |
| 3. 운영 | 운영자 화면에 실제 관람 시간, 빠진 전시, 다음 갈 곳 비율을 보여 준다 | one-page-plan 예측값 표의 '데이터 필요' 항목이 채워짐 |

### 2-5. 한 줄 정리
Smartify는 "**미술관 안에서**, 내가 정한 시간만큼"을 짠다. 우리는 "**기차 시간에서 거꾸로**, 동행에 맞게, 역에서 ACC 여러 건물을 거쳐 다음 갈 곳까지"를 짠다. 엔진 구조(매칭 + 거리 + 시간 제약)는 가져오고, 입력과 범위는 우리 방식으로 바꾼다.
