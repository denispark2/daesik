## 3. 구체화 방안 **[Claude 제안]**

### 3-1. 먼저 정할 것
1. **누가 돈을 내나**: 가게 사장님(광고주) / 인플루언서 / 둘 다
2. **대상 가게**: 빵집·카페만 / 모든 식당 / 특정 지역(광주)
3. **인플루언서 규모**: 팔로워 1천~1만 마이크로·동네 인플루언서 / 큰 인플루언서
4. **채널**: 네이버 블로그 / 인스타 / 숏폼(유튜브·틱톡)
5. **성과 기준**: 게시물 수 / 조회수 / **실제 방문·매출**

### 3-2. 차별점 후보
| # | 아이디어 | 기존 서비스와 다른 점 | 연결되는 우리 자료 |
|---|---|---|---|
| A | **실제 매출로 성과 측정**: 인플루언서별 쿠폰 코드·QR → POS 결제와 연결해 "이 글로 몇 명이 와서 얼마 샀는지" 보여줌 | 기존은 게시물·조회수 중심 | 앱기획안.md POS 연동 |
| B | **동네 인플루언서 매칭**: 가게 반경 안에 사는·자주 다니는 인플루언서 우선 → 단골로 이어질 손님에게 노출 | 전국 단위 모집과 다름 | 빵페스타 결과(일회성 관심) |
| C | **광고 표시 자동 점검**: 게시물에 "유료 광고" 표시가 제목·첫 부분에 있는지 검사, 빠지면 알림 → 사장님 법적 위험 줄임 | 대부분 안내 문구만 붙임 | 2번 표 1·2 |
| D | **가짜·저품질 계정 거르기**: 손님 글 vs 가게·협찬 글 구분, 팔로워 대비 반응률 | 피처링이 비슷한 기능 → 맛집 특화로 좁혀야 함 | 팡슈 사례(본인 계정 글) |
| E | **성과형 정산**: 방문·매출이 생긴 만큼만 비용 | 정액 체험단 비용 부담 해소 | – |

### 3-3. 검증 방법
1. 동네 식당·빵집 사장님 5~10명: 체험단 써봤는지, 비용, 효과 있었는지, 불만(노쇼·질 낮은 글 등)
2. 인플루언서 5명: 어떤 조건이면 동네 가게 협업을 하는지
3. 레뷰에 광고주로 가입해 보지 않고, 공개된 이용 안내·수수료만 확인 (가입은 사용자 판단)

### 3-4. 빵집 앱과 합칠 경우
- 지금 팀 주제(베이커리 사장님 앱)의 **마케팅 기능**으로 넣으면: 생산 계획 + "이번 주 홍보 효과(매출 변화)"까지 한 앱에서 → 별도 서비스보다 차별점이 큼
- 따로 만들면: 레뷰와 정면 경쟁 → A·B·C 중 하나로 좁혀야 함

## 5. 추천 인플루언서 선별 기준 **[Claude 제안]**
4번 결정(동네 인플루언서, 광주 식당, 블로그·인스타·숏폼) 기준. 비율·점수는 예시이고 실제 값은 테스트로 정해야 함.

### 5-1. 기준 7가지
| # | 기준 | 무엇을 보나 | 데이터 얻는 곳 | 비중 예시 |
|---|---|---|---|---|
| 1 | **동네 적합도** (핵심) | 식당과 같은 구·생활권에서 활동하는지, 그 동네 가게 글 비율 | 인플루언서가 입력한 활동 지역 + 공개 게시물의 가게 태그 (**본인 동의 후**) | 30% |
| 2 | **업종·취향 적합도** | 식당 종류(국밥·빵·카페·고기 등), 가격대, 분위기와 평소 글이 맞는지 | 공개 게시물 주제 분류 | 20% |
| 3 | **반응의 질** | 팔로워 수보다 좋아요·댓글·저장 비율, 댓글이 진짜 질문("어디예요?", "가봐야겠다")인지 | 공개 게시물 반응 수, 댓글 내용 | 15% |
| 4 | **후기 진정성** | 전체 글 중 협찬 글 비율, 내돈내산 글 존재, 단점도 쓰는지 | 공개 게시물 | 10% |
| 5 | **광고 표시 준수** | 협찬 글 제목·첫 부분에 "유료 광고" 등 명확히 표시했는지 (2번 표 1 지침) | 공개 협찬 게시물 | 10% |
| 6 | **성과 이력** | 우리 서비스에서 이전 협업 때 쿠폰·QR 사용 수, 재방문 손님 | 서비스 내부 기록 (처음엔 없음) | 10% |
| 7 | **약속 이행** | 방문 일정·마감 지키기, 노쇼, 수정 요청 대응 | 서비스 내부 기록 + 식당 평가 | 5% |

### 5-2. 바로 거르는 조건 (점수와 상관없이 제외)
- 협찬 글에 광고 표시를 안 한 이력
- 팔로워 수에 비해 반응이 비정상적으로 낮거나, 짧은 기간에 팔로워가 급증 (구매 의심)
- 경쟁 식당과 같은 기간 협업 중 (식당이 원하면)
- 노쇼 2회 이상 (서비스 내부 기록)

### 5-3. 채널별로 다르게 볼 것
| 채널 | 더 중요하게 볼 것 |
|---|---|
| 네이버 블로그 | 식당 이름·지역 키워드 검색 시 노출되는지, 글 길이·사진 수, 지도 첨부 |
| 인스타그램 | 저장 수, 위치 태그 사용, 스토리 반응 (인플루언서가 캡처 제공) |
| 숏폼 | 끝까지 본 비율·조회수 (인플루언서가 통계 캡처 제공), 지역 해시태그 |

### 5-4. 매칭 순서 예시
1. 식당 입력: 위치(구·동), 업종, 가격대, 원하는 손님층, 예산
2. 바로 거르는 조건 적용
3. 동네 적합도로 1차 정렬 → 나머지 기준 점수 합산
4. 상위 5~10명 추천 + **추천 이유 한 줄** (예: "상무지구 국밥집 글 12개, 댓글 문의 비율 높음")
5. 협업 후 쿠폰·QR 사용, 식당 평가를 6·7번 점수에 반영 → 다음 추천 개선

### 5-5. 주의할 점
- **개인정보**: 인플루언서가 어디 사는지 추정하지 않음. 활동 지역은 본인이 입력하거나 동의한 범위만 씀. 정확한 집 위치는 저장 안 함
- **공개 게시물 수집**: 플랫폼 이용약관상 자동 수집이 막혀 있을 수 있음 → 공식 API·인플루언서 연동 방식 확인 필요 (**미확인**)
- 팔로워 많은 순으로만 추천하면 레뷰와 같아짐 → 1번 동네 적합도를 가장 크게 둬야 차별점이 유지됨

| 1 | **인플루언서별 쿠폰·QR** | 방문 1명당 비용 = 지불 비용 ÷ 쿠폰 사용 수 / 매출 대비 = 쿠폰 결제 금액 ÷ 비용 | 바로 계산, 인플루언서끼리 비교 쉬움 | 쿠폰 안 쓰고 온 손님은 빠짐 → **최소 효과**로 봐야 함 |
| 2 | **전후 비교 + 비교 가게** | (협업 가게의 전후 매출 변화) − (협업 안 한 비슷한 가게의 같은 기간 변화) | 날씨·계절·연휴 영향을 빼줌 | 비슷한 가게 POS 데이터가 필요 → 데이터 공유 동의 필요 |
| 3 | **시기 나눠 시작** | 같은 조건 가게들을 무작위로 A조(이번 달)·B조(다음 달)로 나눠 시작 | 가장 객관적 (B조가 비교 그룹) | 가게 수가 충분해야 함, 운영 복잡 |
| 4 | **온라인 반응** | 데이터랩 검색량·카카오/네이버 리뷰 수·저장 수 전후 비교 | 공개 데이터라 가게 동의 없이도 가능 | 관심만 보여주고 매출은 아님 (빵페스타 사례처럼) |
| 5 | **재방문** | 쿠폰으로 처음 온 손님이 30일 안에 다시 왔는지 | "단골 만들기" 차별점과 맞음 | 같은 손님 확인에 카드·회원 정보 필요 → 개인정보 동의·가명 처리 필수 |

### 6-3. 업주 화면에 보여줄 값 (예시)
| 항목 | 예시 | 근거 수준 |
|---|---|---|
| 지불 비용 | 30만 원 (음식 제공 원가 포함) | 확정 |
| 쿠폰·QR 방문 | 42명, 결제 126만 원 | 확실한 최소값 |
| 방문 1명당 비용 | 약 7,100원 | 확실한 최소값 |
| 협업 2주 매출 변화 (비교 가게 대비) | +8% (범위 +2~+14%) | 추정 — 범위 같이 표시 |
| 30일 재방문 | 42명 중 9명 | 동의한 손님만 |
| 검색량·리뷰 변화 | 검색 2.1배 → 3주 뒤 1.2배 | 관심 지표 |
※ 숫자는 화면 설명용 **가상 값**

### 6-4. 주의할 점
- 동네 식당은 하루 손님 수가 원래 들쭉날쭉함 → 2주 정도로는 차이가 우연인지 구분이 어려움. "효과 있음/없음" 단정 대신 **범위**로 보여줘야 함
- 비용에는 현금뿐 아니라 제공한 음식 원가도 넣어야 공정한 비교
- 인플루언서 성과 점수(5번 표 6번)를 쿠폰 수만으로 매기면, 쿠폰을 안 쓰는 손님층이 많은 인플루언서가 손해 → 여러 방법을 같이 봐야 함
