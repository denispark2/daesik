## 1. SRT 자동예매프로그램

목표: 원하는 조건(구간·날짜·시간대·인원·좌석)을 넣어 두면 빈 좌석을 찾아 **결제까지 끝낸 예매확정** 상태로 만들기.

### 1-1. 최종 예매확정까지 단계별 실현 방법

| 단계 | 할 일 | 실현 방법 | 자동화 가능 여부 |
|---|---|---|---|
| 0 | 조건 입력 | 출발·도착역, 날짜, 시간대(예: 18~20시), 인원, 일반/특실, 최대 대기 시간 | 가능 |
| 1 | 로그인 | 회원번호·전화번호·이메일 + 비밀번호. 파이썬 라이브러리 `SRTrain`(ryanking13/SRT, 비공식)이 로그인 지원 | 가능 (비밀번호 보관 문제 → 병목 4) |
| 2 | 접속 대기열 통과 | 명절·주말에는 접속 대기열이 걸림 | 일부. 대기열·보안조치를 **우회하면 부정구매** 소지 (병목 2) |
| 3 | 열차 조회 반복 | 조건에 맞는 열차를 일정 간격으로 조회 → 취소표가 나오는지 확인 | 가능 (`SRTrain` 검색 기능). 조회 간격이 짧으면 차단 위험 (병목 3) |
| 4 | 좌석 예약(홀드) | 빈 좌석이 보이면 바로 예약 → 결제 대기 상태가 됨 | 가능 (`SRTrain` 예약 기능) |
| 5 | 알림 | 예약 성공 시 텔레그램·카카오톡·문자로 "결제하세요 + 결제 기한" 알림 | 가능 |
| 6 | **결제 → 예매확정** | SRT 앱·홈페이지에서 결제해야 승차권 발권(확정) | **사실상 불가.** `SRTrain`은 결제 미지원 (병목 1) |
| 7 | 확정 확인 | 승차권 조회로 발권 확인. 결제 기한을 넘기면 예약 자동 취소 → 3단계로 돌아가 다시 찾음 | 가능 |

**현실적인 구성 (제안)**: 0~5·7단계는 자동, 6단계 결제만 사람이 알림 받고 1탭으로 끝냄.
"완전 자동 확정"이 아니라 **"좌석 확보까지 자동 + 결제는 사람"**.

### 1-2. 병목 · 페인포인트

| # | 병목 | 내용 | 영향 |
|---|---|---|---|
| 1 | **결제 자동화** (가장 큼) | 오픈소스 `SRTrain`은 결제를 지원하지 않음. 자동 결제를 하려면 카드번호·비밀번호를 프로그램에 저장해야 하고, 간편결제는 본인인증(지문·비밀번호)이 사람 손에 있음 | 최종 확정 직전에서 막힘. 사람 개입 필요 |
| 2 | **약관 · 법** | SR은 2025년 설에 불법 매크로 의심 회원 9명(6,400만 건 접속)을 경찰에 수사 의뢰. 2026-01 "보안조치 우회 부정구매 금지·벌칙 신설" 철도 관련 개정안 발의 (통과 여부 확인 못 함). 되팔기(암표)는 2025년 철도사업법 개정으로 단속 근거 생김 | 개인용이라도 계정 정지·수사 위험. 서비스로 배포하면 더 큼 |
| 3 | 차단 · 탐지 | 짧은 간격 반복 조회는 매크로로 탐지됨. 조회 간격을 늘리면 취소표를 놓침 | 속도 ↔ 안전 맞바꿈 |
| 4 | 비밀번호 보관 | 로그인을 자동으로 하려면 SRT 비밀번호를 PC·서버에 저장해야 함 | 유출 위험. 남에게 서비스하면 남의 비밀번호를 맡게 됨 |
| 5 | 비공식 API 변경 | `SRTrain`은 SRT 공식 API가 아님. SRT 쪽 주소·방식이 바뀌면 깨짐 (2.0.0 때 API 주소 변경 반영 이력) | 유지보수 부담, 명절 직전에 고장 나면 쓸모 없음 |
| 6 | 결제 기한 안에 사람이 응답해야 함 | 예약 후 결제 기한을 넘기면 자동 취소. 알림을 못 보면 좌석을 잃음. 일반 예매의 결제 기한(예약 후 몇 분)은 공식 안내에서 **확인 못 함** (명절 예매는 결제 기간 별도 공지) | 6단계 실패 → 7단계에서 다시 찾기 반복 |
| 7 | 취소표 타이밍 예측 불가 | 언제 표가 풀릴지 모름 → 오래 켜 둬야 함 (PC 상시 실행·서버 비용) | 운영 비용 |
| 8 | 노쇼 위약금 | SRT는 노쇼 위약금 기준을 강화함 (출발 3시간 전 취소 기준 보도). 자동으로 여러 표를 잡아 두고 버리면 위약금 | 여러 열차 동시 예약 전략 쓰기 어려움 |
| 9 | 기존 서비스와 차별점 | SRT 자체 예약대기 기능, 2025년 KTX·SRT 통합 앱 출시 보도 → "공식 앱으로도 되는데 왜?"에 답해야 함 | AX 아이디어 선정 시 설득력 |

### 1-3. 아이디어 선정용 메모

- 기술 난이도: 낮음~중간 (0~5단계는 오픈소스로 하루 안에 시제품 가능할 것으로 봄 — 직접 만들어 본 것은 아님)
- 막히는 곳: **결제(1)와 약관·법(2)**. 둘 다 기술이 아니라 규칙 문제라 교육 과제로 풀기 어려움
- 그대로 내면 "매크로 프로그램"으로 보일 수 있음 → 선정한다면 **조회 간격을 사람 수준으로 제한 + 결제는 사람**인 "취소표 알림·좌석 확보 비서"로 범위를 줄이는 쪽이 안전 (제안)

### 1-4. 확인 못 함
- SRT 이용약관의 자동화 프로그램 금지 조항 원문
- 2026-01 발의된 매크로 금지 개정안의 통과·시행 여부 (국회 의안정보시스템에서 확인 필요)
- 일반 예매의 예약 후 결제 기한
- SRT 예약대기 기능의 현재 조건 (구간·횟수 제한 등)
